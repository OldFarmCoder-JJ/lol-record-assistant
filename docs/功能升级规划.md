# LOL 战绩助手功能升级规划

规划日期：2026-10-30。当前本地安装版本：v1.3.4。第一批已完成开发、验证和本地打包；第二、三批和局内海克斯识别仍为后续规划。

## 产品方向

围绕「对面先出英雄，我快速找到他，再从自己会玩的英雄里挑克制」和「海斗备战席快速比较胜率」优化。排行继续占主区域，细节按需展开，个人战绩继续独立切页。

## 当前已有，继续保留

- 国服/全球/韩服排行及攻略，对面已锁定英雄在当前分路榜置顶、红框标注，保留原名次。
- 克制头像列，以及海斗备战席按胜率置顶、前三金框。
- 手动切换模式刷新、客户端识别本人分路后刷新，丢弃过期请求。
- 最近20场排位、原分路累计榜、官方历史接口补读、本地图片缓存。
- 校验安装包、旧版备份、更新失败回滚；仅在明确要求发布时打包。

## 升级优先级

| 优先级 | 功能 | 使用场景与预期行为 | 验收重点 |
| --- | --- | --- | --- |
| P0 | 断网与连接恢复 | 同一模式/服务器/段位/分路有缓存时先显示并标明缓存时间，后台更新；失败时可重试。不同模式不能显示成同一份旧列表。 | 断网、重连、快速切换、换号后不串数据；保留现有数据版本和统计日期。 |
| P1 | 克制推荐结合个人英雄池 | 对面剑圣置顶后，右侧克制头像标记「已收藏／近期玩过」。若有更多对位候选，允许优先查看自己收藏的；没有熟悉候选时保留全部来源推荐。 | 收藏与本人战绩分开标注；不能把“玩过”当作“熟练”；近期小样本不直接认定强弱。 |
| P1 | 自动识别当前游戏模式 | 进入选人时，海斗自动切到海斗，已支持的峡谷队列自动切到峡谷，再跟随本人分路。提供自动跟随开关。手动改选后暂时尊重用户选择。 | 仅使用明确支持的队列；重复事件不抖动、不反复覆盖手动选择；不打断正在查看的个人战绩。 |
| P1 | 克制头像可点击、显示可选状态 | 点击推荐头像直接查看该英雄攻略。对候选标记已禁用、已被选或未拥有等已确认状态；未知则不判断。 | 推荐英雄身份和攻略一致；对面英雄本身继续显示，不能因为不可选而从目标排行消失。需先验证客户端可选字段。 |
| P2 | 对阵详情按需展开 | 点击对面英雄旁的小按钮，查看更多「选谁打他」、我方视角的对阵胜率，以及本人玩过的次数。使用轻量弹层或替换当前列表，保留返回入口。 | 不增加常驻大面板；整体胜率与对阵胜率分开；来源、版本、分路相符，无对位数据就明确显示缺失，未公开场次不编造。 |
| P2 | 最近排位增加简要复盘 | 在现有20场基础上，可切换最近50/100场，并增加英雄使用次数、分路分布和逐场KDA。场次不足时展示实际范围。 | 单双排/灵活组排可区分；重开不计胜负；KDA只使用已取得的真实字段，不从缺失数据推断。 |
| P2 | 海斗备战席显示收藏标记 | 保持当前胜率排序和前三金框，在头像或名称旁增加收藏标记；需要时展示本人海斗历史表现。 | 不能把排位个人胜率当成海斗个人胜率；收藏标记不能改变金框“当前可选胜率前三”的含义。 |

## 建议分批交付

### 第一批：减少查找与重复操作

状态：源码已完成。收藏与近期标记、缓存降级、手动暂停自动跟随等回归通过；真实客户端排行与本人20场排位已只读验证。真实选人阶段的模式切换仍待现场使用验证。

1. 先完成连接恢复与同条件缓存展示的边界处理。
2. 增加个人英雄收藏，允许在攻略页或英雄行收藏。
3. 在既有克制头像、海斗备战席旁标记收藏和近期玩过。
4. 增加模式自动跟随开关，并验证与手动浏览的切换规则。

交付效果：进入选人后助手跟随当前模式和分路；找到对面英雄后，一眼看见克制候选里哪些自己会考虑使用。保持当前窗口尺寸与排行可见面积。

### 第二批：从看到候选到确认选择

增加候选头像点击、已确认可选状态、按需展开的对阵详情。结合来源数据与本人记录展示，不使用不透明的综合评分替代实际胜率与场次。

### 第三批：战绩与海斗细化

增加50/100场复盘、KDA、按排位类型筛选，以及独立的海斗个人表现。优先复用当前账号隔离缓存与官方历史补读，避免另起一套采集逻辑。

## 局内海克斯推荐：独立研究项

当前未能自动读取画面中的三个候选。先验证候选获取方式和识别准确性，再讨论推荐规则、刷新建议与展示入口。识别不确定时应明确提示并停止判断，不恢复此前识别无效、占空间的自动小窗。

## 开发与发布方式

- 每批先源码预览，验证模式切换、分路识别、重复事件、断网、换号和数据不足等场景。
- 保留现有海斗排序、Counter定位和最近20场排位的回归检查。
- 真实客户端验证和模拟数据验证分别记录。
- 用户明确要求打包后才生成新安装包；E盘替换前备份，发布GitHub另按用户要求执行。
