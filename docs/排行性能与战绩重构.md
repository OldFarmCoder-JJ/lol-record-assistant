# 排行性能与战绩界面重构

本轮为源码更新。已安装的 E盘 v1.3.4、桌面快捷方式及 GitHub Release 没有由本轮更新。双击仓库根目录「启动源码版.cmd」可运行修改后的版本。

## 界面与操作

- 收藏星标放到排行榜最左侧独立一列，不再覆盖英雄头像；也可以右键收藏。Tab 聚焦星标后可用空格操作。
- 近期同模式战绩放到英雄名下方，显示实际场次与胜负。克制头像使用细色环标记，悬停查看收藏状态及近期战绩。
- 保留对面锁定英雄置顶、原始排行名次、紧凑克制头像，以及海斗备战席按胜率排序和前三金框。
- 点击「战绩统计」查看本人记录。页面隐藏公共排行榜的服务器、段位、版本等筛选项；「返回排行」回到原页面。
- 最近对局显示实际已读取的最近20场；可分别看全部排位、单／双排、灵活组排或海斗。
- 「英雄使用统计」按使用场次、最近使用时间排序。玩过1场就显示，不再设5场门槛，也不按个人胜率排名。
- 英雄统计可选择全部分路或指定分路；海斗不按分路筛选。重开和待确认结果单独统计，不算作失败。场次包括这些记录，悬停「场次」或「胜 / 负」可查看每个英雄的完整结果组成。
- 所有个人统计仅代表当前账号已读取的范围；每次最多读取近期200场，本地累计最多保留2000场，不代表生涯全部战绩。

## 性能改造

旧版返回排行时会用磁盘缓存重建一次整表，再用服务返回值重建第二次；整列列表还使用了逐项测量的流式布局。新版改为纵向布局，并复用未变化的英雄行。

- 15分钟内返回相同筛选的已加载排行，直接复用页面，保留排序、滚动位置和该榜的数据版本。超过时限重新读取；点击「刷新」始终请求更新。
- 海斗、峡谷切换后复用相同内容的行；控件池上限360行，旧行明确释放，不随切换次数持续增加。
- 首次创建行时分成短批次，在 GUI 线程处理控件，同时给窗口输入和绘制让出时间。中途改选会丢弃旧批次。
- 缓存读写在后台线程执行；写入串行化，较旧响应不能回写覆盖较新的缓存。
- 相同数据不重复构建，收藏状态不变时不重复刷新样式；头像缩放结果按尺寸及屏幕缩放比例复用。
- 合并同一轮事件循环中的重复筛选通知。旧请求、旧错误和旧账号资料不能覆盖新选择；退出时停止后台加载。

固定模拟数据为峡谷55行、海斗170行。改造前切换中位耗时约2.28秒，改造后约0.10–0.15秒；最终单独复测为104.83毫秒，从攻略返回已加载排行18.98毫秒。首次整表创建仍需时间，但输入不会等待整张表创建完才响应。这是本机固定负载的结果，实际数据读取还受网络、图标缓存和机器性能影响。

复测命令：

```powershell
.\packaging-env\Scripts\python.exe tools\benchmark_rankings.py
.\packaging-env\Scripts\python.exe verify_desktop_redesign.py
```
